The page you're on right now. A static, dependency-free site with no build step, no package manager, and no framework. The home page models my work as an ontology: me, the roles I've held, and the projects I've built, as 3D objects on a slab with typed links between them, tethered to the skills each one uses. Every page reads the same data file, so nothing about a project is typed in two places.

The data lives in site.js: PROJECTS, ROLES, and SKILLS. A project lists the skills it uses and any true links it has, like Dataform Slots being built at Gordon Food Service. The ontology, the case-study grid, the about page, and each case study's roadmap all read from those three arrays.

ontology.js only decides presentation: where each object sits on the slab and which line-art model draws it. The models are built from boxes and cylinders in three.js, outlined with edge lines and an inverted-hull silhouette, and lit flat so they read like an illustration. Labels, link pills, and the property panel are HTML positioned over the canvas each frame, so text stays crisp.

The skill lines leave from ports on the slab's back edge, ordered left to right like their chips, so they fan up without crossing. Hovering an object lights its links and skills; hovering a skill lights the objects that use it.

site.js: a project is one entry. Its skills and links are what the ontology draws.

      skills:['GCP', 'SQL', 'REST APIs'],
      related:[['gfs', 'Built at']],
      // … name, desc, stats, roadmap
    }
];
