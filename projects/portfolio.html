This Site

portfolio · JavaScript + three.js · Apr 2026 – present

Problem

A resume lists roles and projects, but not how they connect: which skills came from which job, or which project grew out of which. I wanted one place that shows that, with a short write-up behind every project.

Approach

The home page is an interactive 3D map of my roles, projects, and skills, with labeled links between them. Click any object to open its details or its case study. Every page reads from one data file, so nothing about a project is typed in two places.

Under the hood: a static site with no build step, no package manager, and no framework. site.js holds the data and the shared header, footer, and project pages; ontology.js draws the scene in three.js with line-art models and HTML labels positioned over the canvas each frame.

The data lives in site.js: PROJECTS, ROLES, and SKILLS. A project lists the skills it uses and any true links it has, like the BigQuery Cost Optimizer being built at Gordon Food Service. The ontology, the case-study grid, the about page, and each case study's roadmap all read from those three arrays.

ontology.js only decides presentation: where each object sits on the slab and which line-art model draws it. The models are built from boxes and cylinders in three.js, outlined with edge lines and an inverted-hull silhouette, and lit flat so they read like an illustration. Labels, link pills, and the property panel are HTML positioned over the canvas each frame, so text stays crisp.

The skill lines leave from ports on the slab's back edge, ordered left to right like their chips, so they fan up without crossing. Hovering an object lights its links and skills; hovering a skill lights the objects that use it.

site.js: a project is one entry. Its skills and links are what the ontology draws.
