Kalshi Market Pipeline & Lakehouse

data pipeline · Python, AWS, Databricks · Aug 2026 – present
In progress. The source repository is private, so there is no public link; I’m happy to walk through the code in an interview.

Problem

Prediction-market prices are supposed to be probabilities: an event trading at 70¢ should happen about 70% of the time. Checking that (market calibration) needs a complete, clean record of every market and every trade. Kalshi only serves that data through a rate-limited API, and a pipeline that drops or double-counts trades would quietly skew the answer.

Approach

An asynchronous Python service polls Kalshi’s API around the clock. To keep up with 175K+ active markets within a 20-requests-per-second limit, it tracks each market’s status and skips the ones that haven’t changed. Raw data lands in daily files, is copied to AWS S3 every day, and Spark jobs on Databricks, scheduled by Airflow, deduplicate the trades and build the tables used for calibration analysis.

Under the hood: asyncio + aiohttp with client-side RSA-PSS request signing and an in-memory token-bucket rate limiter with jittered backoff. Ingestion is idempotent and loss-free: records land in Hive-style, date-partitioned JSONL with atomic checkpoint markers, and out-of-order settlement transitions are handled explicitly. PySpark jobs move data from Bronze to Silver Delta Lake tables, and the calibration tables are modeled as a star schema.

A hand-rolled token bucket. Continuous refill, an asyncio.Lock held only around the check-and-decide step and released before any sleep, and a retry loop rather than recursion. Building it surfaced a self-deadlock from re-acquiring a non-reentrant lock and a double-release error. On startup the client reads the account's real limits and rebuilds the bucket, instead of trusting a guessed tier.

Retries live in one place. Every endpoint is a thin wrapper over one request method that owns rate limiting, signing, and status-code branching. Exhausted retries raise instead of returning None, so a failure surfaces where it happened rather than as a TypeError three calls later. The signature is recomputed inside the retry loop because it embeds a timestamp.

Bronze is plain JSONL, partitioned by ingestion date. Writing never has to inspect the payload to pick a file, and once a day passes its file is finished for good. A database was considered and rejected, including SmallDB: Bronze is written and read sequentially in full, with no key lookups for an LSM tree to speed up.

Resuming after a crash, three ways. Trades walk forward in one-hour windows with a checkpoint written only after the window is flushed to disk. The first version resumed from the newest stored timestamp and silently skipped data, because the API returns trades newest-first. One-shot historical jobs use completion markers; candlesticks use a set difference against what Bronze already holds.

Markets are state, trades are events. "Everything after timestamp X" fully describes new trades, but a known market can move from closed to settled without being new. A timestamp cutoff would miss exactly the transitions the project cares about, so markets get a separate settlement worklist.
